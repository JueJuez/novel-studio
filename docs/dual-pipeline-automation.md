# 双管线开发自动化流程

更新日期：2026-10-31。状态：生效。

本文件定义 [dual-pipeline-development-plan.md](dual-pipeline-development-plan.md)（下称"计划"）的自动化执行协议：会话如何分批实施任务、如何记录证据、何时提交推送、何时验收。计划文件仍是任务与验收的唯一真源；本文件只规定"怎么推进"，不复制任务清单。

## 1. 批次循环

每个开发会话（人工开启或定时自动化触发）执行一个批次，批次大小固定为 **2 个任务**：

1. **开工检查**
   - `git pull --ff-only origin main`；若工作区存在不属于本流程的未提交改动，停止并报告，不回滚他人改动。
   - 若存在 `.batch-lock` 且距其时间戳不足 3 小时：说明另一批次可能正在进行，本次直接结束并报告。否则 `date +%s > .batch-lock`（该文件已 gitignore）。
2. **选取任务**：按计划第 7 节表格，从 P0 起按 ID 顺序取状态为"待实施"的前 2 个任务；存在"进行中"的任务时优先续作（先读其证据与日志，再补完剩余部分）。
3. **实施**：遵守计划的模块边界与验证要求。P0—P4 一律使用 mock/fixture，不发起真实云端模型调用；真实调用只出现在 P5-02 与第 3 节验收。
4. **记录证据**：任务完成后，在计划第 7 节对应行把状态改为"已完成"，并在该行"验证与依赖"列追加证据（提交号、日志/文档路径、关键结果）。禁止把未验证项标为完成；做不完时状态记"进行中"并写明已完成到哪一步，批次正常结束，下批续作。
5. **收尾**：`rm -f .batch-lock`；按仓库 conventional commits 风格提交（`feat:`/`fix:`/`docs:`/`test:` 等），然后 `git push origin main`。推送失败时保留本地提交并报告，不得 force push。
6. 若计划仍有未完成任务：本会话到此结束，等待下一个会话继续。若 P0—P5 全部完成：进入第 3 节验收。

## 2. 凭证与配置

- 云端模型凭证保存在仓库根 `.env.local`（已 gitignore，不入库）：
  - `NOVEL_LLM_BASE_URL`：`https://api.commandcode.ai/provider/v1`
  - `NOVEL_LLM_API_KEY`：密钥本体只存在该文件，任何文档、日志、代码、提交中不得出现明文。
  - `NOVEL_LLM_MODEL`：`deepseek/deepseek-v4-flash`
- 2026-10-31 已用该凭证完成连通冒烟：`POST /chat/completions` 正常返回（OpenAI 兼容），模型应答与 usage 完整。
- 工程侧接入模型配置时走现有 provider/配置体系（见 config.example.jsonc 与现有 usage/成本记录），不得为云端 API 另建第二套客户端。

## 3. 验收测试（P0—P5 全部完成后执行）

1. 读取 `.env.local`，把真实模型配置写入引擎现有配置体系（本地配置文件，不入库）。
2. **短篇验收**：通过新短篇管线端到端生成一篇 3—5 场景短篇，覆盖：创意澄清 → 结构 → 场景计划 → 草稿 → 局部修改与审核 → 全文检查 → 导出。作者确认点由执行会话代为确认，报告中明确标注。
3. **长篇验收**：通过原引擎生成一个小型长篇窗口（单弧 1—2 章），验证初始化 → 整弧预演/推演 → 逐章渲染 → 审核 → 封存链路可用。
4. 两份正文与用量/成本/耗时记录保存到 `output/acceptance/`（gitignored）；报告写入 `docs/dual-pipeline-acceptance-report.md`（不含密钥）。
5. **通过标准**：两条管线均产出完整正文、关键门禁未被绕过、导出成功；任一失败则修复后重测（回到第 1 节批次循环）。
6. 作者评阅（冲突/结局是否成立、人物一致性、语言可读性等语义结论）无法由自动化替代：报告生成后标"待作者评阅"，由作者人工给出结论后 MVP 才算完整交付（对应计划第 8 节）。

## 4. 自动化触发

- 定时自动化（ZCode automation）每小时触发一次，执行第 1 节的一个批次；若无可做工作（全部完成且已验收），仅输出一行状态并结束。
- 自动化会话不得创建、修改或删除任何自动化任务。
- 人工会话与自动化并存时依赖 `.batch-lock` 互斥；如需停止自动推进，删除对应自动化即可。
